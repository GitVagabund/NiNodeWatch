# NiNodeWatch 0.1.1

NiNodeWatch — диагностический SKSE-плагин для Skyrim Special Edition 1.5.97.

Он отслеживает операции с `NiNode` и массивами дочерних узлов сцены и сохраняет подробный контекст вокруг сбоев, связанных с обработкой `NiNode::children`, `NiTObjectArray` и NIF-сценами.

Плагин предназначен для сложных CTD, когда обычный Crash Logger не позволяет однозначно определить проблемный меш или узел сцены.

## Поддерживаемая версия

- Skyrim Special Edition 1.5.97
- SKSE64 для Skyrim 1.5.97

На данный момент NiNodeWatch собран специально для Skyrim SE 1.5.97.

На других версиях Skyrim плагин не должен использоваться.

## Что делает NiNodeWatch

Плагин отслеживает ряд операций с `NiNode` / `NiTObjectArray` и записывает:

- имена узлов;
- указатели на дочерние объекты;
- состояние массива `children`;
- `capacity`, `size` и `freeIdx`;
- ID потока;
- стек вызовов;
- контекст scene graph;
- имена NIF и связанных узлов;
- access violation, возникающие во время обработки NiNode.

При обнаружении подходящего исключения NiNodeWatch создаёт incident-log с историей последних операций непосредственно перед сбоем.

## Реальный пример

NiNodeWatch был создан во время диагностики воспроизводимого CTD в Каирне Душ.

Обычные crash-логи не позволяли определить конкретный объект, вызывающий сбой.

Во время проблемного запуска NiNodeWatch неоднократно зафиксировал непосредственно перед исключением:

`dlcsoulcairnwisp.nif`

и узел:

`DlcSoulCairnWisp`

во время обработки дочерних элементов NiNode.

После отключения размещённых экземпляров Whispering Spirit в Каирне Душ воспроизводимый CTD исчез во время последующего тестирования.

Это не означает, что сам ванильный NIF обязательно является дефектным во всех конфигурациях Skyrim.

Имя NIF или узла в NiNodeWatch следует рассматривать как сильную диагностическую зацепку, а не как абсолютное доказательство того, что именно этот файл является единственной причиной сбоя.

## Установка

Установите архив релиза через Mod Organizer 2 или другой менеджер модов.

DLL должна находиться по пути:

`Data/SKSE/Plugins/NiNodeWatch.dll`

После этого запускайте Skyrim через SKSE как обычно.

## Логи

NiNodeWatch создаёт диагностические incident-логи при обнаружении соответствующего исключения.

Имена файлов выглядят примерно так:

`NiNodeWatch-incident-YYYYMMDD-HHMMSS-....log`

В них находится история последних операций NiNode непосредственно перед зарегистрированным исключением.

## Технические особенности

NiNodeWatch 0.1.1 рассчитан на Skyrim SE 1.5.97.

В исследованном CTD исключение происходило в области обработки NiTObjectArray::Compact.

Плагин также отслеживает операции изменения массива дочерних элементов NiNode, включая SetAt и связанные операции.

NiNodeWatch является диагностическим инструментом и не пытается отменять игровые операции или автоматически предотвращать CTD.

Исключения, возникающие внутри других SKSE-плагинов, могут игнорироваться, если они не относятся к исследуемому пути обработки NiNode.

Поскольку hooks добавляют дополнительную диагностическую нагрузку, NiNodeWatch рекомендуется использовать именно во время поиска причины CTD, а после завершения диагностики удалить или отключить.

Важно

NiNodeWatch не исправляет автоматически:

повреждённые NIF;
конфликтующие плагины;
ошибки скриптов;
повреждённый scene graph;
несовместимые SKSE-плагины.

Его задача — показать, что происходило с NiNode непосредственно перед сбоем, и помочь сузить круг подозреваемых объектов.

Сборка из исходников

Проект использует CMake и vcpkg.

Для сборки используются:

CMakeLists.txt
vcpkg.json
vcpkg-configuration.json

Также в репозитории находится PowerShell-скрипт:

build.ps1

Для сборки потребуется:

Visual Studio 2022 с workload Desktop development with C++
Git for Windows
CMake

Откройте Developer PowerShell for VS 2022 в каталоге проекта и выполните:

Set-ExecutionPolicy -Scope Process Bypass
.\build.ps1

Скрипт подготовит зависимости и соберёт проект.

Готовая DLL будет находиться в:

dist\NiNodeWatch\SKSE\Plugins\NiNodeWatch.dll
